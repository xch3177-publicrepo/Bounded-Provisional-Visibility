The only thing that survives from it is the S1 *direction*: 4 of 5 paired

destroying block identity. The re-run must regenerate throughput *and* P99
together; quoting run 2's throughput beside a new run's P99 would source one
performance conclusion from two different sets of run conditions.

## Run 1 (pilot) — the three defects that forced the redesign

Environment was genuinely Milvus standalone v2.4.15 over gRPC (not Lite): the
container was healthy on :19530, and latencies ran 3 orders of magnitude above
the in-process Lite baseline (S5 query P99 420 ms vs 0.3 ms).

| Experiment | Verdict | Defect |
|---|---|---|
| S1 throughput / P99 | **invalidated** | Baselines ran grouped (B1,B1,B1,…,B4,B4,B4), so B1 alone absorbed cold start and measured *slower* (837 items/s) than the full protocol B4 (1021) — the opposite of what the protocol can do. Query samples were also incomparable: 621 (B1) vs 9031 (B2) over windows whose length was set by ingestion speed. |
| S2 δ_prop | **diagnostic only** | δ_prop (~470 ms) was the same order as a single Strong-consistency search (~420 ms), so the probe's own cost was inseparable from the delay it measured. δ_prop was never separately identified. |
| S5 HNSW | **inconclusive** | dim=32 (the paper specifies 384), and no flush/index build, so vectors stayed in an unsealed growing segment that Milvus brute-force scans. `index_type` had no effect; all three rows were bit-identical and `cond_recall=1.0` is an artefact, not ANN accuracy. |

## What changed for the re-run

- **S1**: fixed measurement window, fixed open-loop query arrival rate,
  randomized paired blocks, global + per-cell warm-up, paired per-block
  B4/B1 ratio instead of a cross-run point estimate.
- **S2**: two-layer probe — a lightweight scalar point lookup (state visibility)
  alongside the full ANN search (query-path confirmation) — and the metric is
  renamed to confirmation delay. Note `set_visible()` is an **upsert** in Milvus
  (delete+insert), so a hide traverses the write path; that is a property of
  this implementation, not of in-index filtering in general.
- **S5**: 384-d vectors matching the paper, mandatory flush + index build +
  reload, and `index_type_effective` / `index_state` / `load_state` recorded per
  row. Success is a readable recall–latency trade-off; observing **no** recall
  loss is a valid outcome and simply does not unlock P1.
- All records now carry `server_version`, `server_uri`, `deployment_mode`, and
  the runner refuses to emit E3 records from Milvus Lite at all.
